# 出会い方診断サイト 収益導線設計メモ

## 目的

* 診断結果やコラムから、ユーザーの状態に合った外部導線へ自然につなげる。
* 不安を煽らず、選択肢の整理・気持ちの整理・次の行動の補助として導線を置く。
* 外部URL実装前に、どのページにどの導線を置くかを整理する。

## 前提

* 現時点では外部URL・販売URL・アフィリエイトURLは未実装。
* 今後追加する可能性がある導線：

  * 占い鑑定販売
  * note
  * ブログ
  * マッチングアプリアフィリエイト
  * 電話占いアフィリエイト
  * 結婚相談所アフィリエイト
* 断定表現は避ける。
* 「必ず出会える」「結婚できる」「成功する」などの表現は使わない。
* PR表記や広告表記が必要な箇所は、実装時に明記する。

## ページ別導線案

### トップページ /

* 目的：サイト全体の入口。
* 優先導線：

  1. 診断ページ /diagnosis
  2. コラム一覧 /articles
  3. 気持ち整理 /fortune
* 外部導線は強く出しすぎない。
* 将来的には下部に「次にできること」枠として、note・ブログ・占い鑑定への控えめな案内を置く。

### 診断ページ /diagnosis

* 目的：診断完了後に、結果タイプに合わせて次の選択肢へつなげる。
* 優先導線：

  1. 結果タイプ別おすすめコラム
  2. /matching-apps
  3. /fortune
  4. /articles
* 外部導線案：

  * matching_app / marriage_app：マッチングアプリ比較・アフィリエイト導線
  * agency：結婚相談所比較・資料請求系アフィリエイト導線
  * self_reflection / rest：占い鑑定、note、ブログ、電話占い導線
  * introduction / community / event：コラム・ブログ導線中心
* 実装時は、いきなり外部ボタンを大きく出すより、内部コラムを挟んでから外部導線へつなげる。

### /matching-apps

* 目的：マッチングアプリを選択肢のひとつとして整理するページ。
* 外部導線候補：

  * マッチングアプリアフィリエイト
  * アプリ比較記事
  * 登録前チェックリスト
* 表現方針：

  * 「おすすめランキング」よりも「選ぶ前に確認したいこと」寄り。
  * 安全面、目的、年齢層、真剣度、料金、使いやすさを比較軸にする。
* 実装時の注意：

  * PR表記を入れる。
  * 特定サービスを断定的に推奨しない。
  * 外部リンクには target="_blank" と rel="noopener noreferrer" を付ける。

### /fortune

* 目的：迷った気持ちを整理する補助ページ。
* 外部導線候補：

  * 占い鑑定販売
  * 電話占いアフィリエイト
  * note
  * ブログ
* 表現方針：

  * 「占いで答えを決める」ではなく、「気持ちを整理する補助」として案内する。
  * 不安を煽らない。
* 導線順の案：

  1. 自分で整理するコラム
  2. note / ブログ
  3. 占い鑑定
  4. 電話占い

### /articles

* 目的：コラム一覧から、内部回遊を作る。
* 外部導線候補：

  * 記事下部に控えめな関連導線を置く。
  * 全記事に同じ外部リンクを入れるのではなく、記事テーマに合わせて出し分ける。
* 実装方針：

  * コラム一覧自体は内部導線中心。
  * 外部導線は各記事本文末尾のCTAで自然に出す。

## 次にマッチングアプリASPリンクを追加するときの方針

### 追加候補ページ

* /matching-apps
* /articles/before-starting-matching-apps
* 診断結果の matching_app / marriage_app タイプ付近

### 優先順位

1. まず /matching-apps にPR表記付きの比較導線を追加する。
2. 次に /articles/before-starting-matching-apps の末尾CTAから /matching-apps へ誘導する流れを維持する。
3. 最後に診断結果の matching_app / marriage_app タイプから、直接外部リンクではなく、まず /matching-apps へつなぐ形を検討する。

### 表現方針

* 「おすすめNo.1」「必ず出会える」「恋人ができる」「成功する」などの断定表現は使わない。
* ランキング形式よりも、目的・年齢層・真剣度・料金・安全面・使いやすさの比較軸で整理する。
* 特定サービスを強く推しすぎず、「選択肢のひとつ」として案内する。
* 登録を急がせる表現は避ける。
* 利用前に公式情報、料金、本人確認、安全面を確認するよう促す。

### 実装時の注意

* 外部リンクには target="_blank" と rel="noopener noreferrer" を必ず付ける。
* PR表記または広告リンクを含む旨を、導線付近に分かりやすく表示する。
* /advertising への内部リンクを近くに置く。
* いきなり複数ASPリンクを大量に入れず、最初は少数の導線から確認する。
* 外部URLを入れた後は、内部リンク・外部リンク・スマホ表示・ビルド確認を行う。
* sitemap / robots / metadataBase / Google verification は原則変更しない。
* 診断ロジックは変更しない。

### 実装後の確認項目

* /matching-apps が表示崩れしていない。
* PR表記が目立ちすぎず、でも見落とされにくい。
* 外部リンクに target="_blank" と rel="noopener noreferrer" が付いている。
* /advertising への内部リンクがある。
* /articles/before-starting-matching-apps から /matching-apps への流れが維持されている。
* 診断結果からの導線が強すぎない。
* スマホ表示でカードやボタンが押しやすい。
* npm run lint / npx tsc --noEmit / npm run build が成功する。
